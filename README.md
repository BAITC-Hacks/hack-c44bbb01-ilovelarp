# Каталог бизнес-задач с геймификацией полноты (AI Sana MVP)

MVP по кейсу «Единый кейс по геймификации практических заданий»: представитель бизнеса
превращает черновик потребности в карточку задачи, система оценивает её полноту рейтингом
0–100 и публикует в открытом каталоге; студенческие команды откликаются, бизнес сам вручную
выбирает, с кем работать. Автоматическое назначение команд запрещено кейсом — и в этом MVP
его физически нет.

## Запуск

Зависимостей и сборки нет — это обычные HTML/CSS/JS файлы.

1. Откройте `index.html` в браузере двойным кликом — **или**, что надёжнее (гарантирует работу
   localStorage во всех браузерах), поднимите локальный сервер из папки проекта:
   ```
   python3 -m http.server 8000
   ```
   и откройте `http://localhost:8000`.
2. Приложение стартует с демо-данными (см. «Тестовые сценарии» ниже) — регистрация не нужна,
   роль переключается кнопками в сайдбаре.

Если браузер блокирует `localStorage` для `file://` (так бывает в Firefox), приложение не
падает — просто не сохраняет между перезагрузками страницы; для демонстрации это не мешает.

## Архитектура

Без фреймворков и без сборщика — чтобы за 5 часов не тратить время на тулинг. Все файлы —
обычные `<script>` в `index.html`, общее состояние держится в глобальных неймспейсах
(`Constants`, `Helpers`, `Rating`, `State`, `AI`, `Router`, `Views`).

```
index.html            разметка-оболочка: сайдбар + точка монтирования #main
styles.css             светлая адаптивная тема, все стили
data/seed.js            синтетические данные (window.SEED_DATA) — НЕ через fetch,
                         чтобы работать и при открытии файла напрямую
js/constants.js         название и 9 содержательных полей карточки, 7 категорий рейтинга с весами, 4 уровня готовности,
                         список отраслей, банк уточняющих вопросов
js/helpers.js           мелкие UI-хелперы: экранирование, даты, рендер бейджей/полосок рейтинга
js/rating.js            формула рейтинга (см. ниже) — чистая функция, не зависит от DOM
js/state.js             хранилище поверх localStorage: CRUD для задач/откликов, роль, AI-конфиг
js/ai.js                AI-функция: уточняющие вопросы + сборка карточки.
                         Внешний API (OpenAI-совместимый) с фолбэком на офлайн-заглушку
js/router.js            хэш-роутер (#/wizard, #/catalog, ...) + рендер навигации в сайдбаре
js/views/wizard.js       мастер бизнеса: черновик → вопросы → карточка+рейтинг → публикация
js/views/myTasks.js      список своих задач (черновики / опубликованные)
js/views/inbox.js        входящие отклики по задаче, ручное принять/отклонить
js/views/catalog.js      каталог для студентов: сортировка по рейтингу, фильтры
js/views/taskDetail.js   карточка задачи + форма отклика команды
js/views/myProposals.js  поданные и одобренные заявки выбранной команды
js/main.js               точка входа: регистрация роутов, переключатель ролей, настройки AI
test/smoke.js            сквозной smoke-тест на jsdom (см. «Проверка» ниже)
```

Ролей-логина нет намеренно (см. «Ограничение объёма» кейса — полноценная авторизация не
требуется): переключатель «Я бизнес / Я студенческая команда» в сайдбаре — это весь механизм
ролей, всё крутится в одном браузере на localStorage.

### Модель данных

```
Task {
  id, status: 'draft' | 'published', industry,
  fields: { title, context, need, users, data, constraints,
            expectedResult, successCriteria, contact, interactionFormat },
  rating: { total, level, breakdown[], missing[] },   // пересчитывается при каждом сохранении
  clarifyingQuestions[], clarifyingAnswers{}, lastAISource: 'ai' | 'stub'
}
Proposal {
  id, taskId, teamName, idea, plan, deadline, prototypeLink,
  status: 'pending' | 'accepted' | 'declined', progressPoints
}
Team { id, name, interests[], skills[], technologies[] }
```

## Формула рейтинга (0–100)

Ровно по таблице «Основная механика геймификации» кейса, реализовано в `js/rating.js`:

| Категория | Поля карточки | Вес |
|---|---|---|
| Контекст и потребность | context, need | 20 |
| Данные и материалы | data | 20 |
| Ожидаемый результат | expectedResult | 15 |
| Критерии успеха | successCriteria | 15 |
| Ограничения | constraints | 10 |
| Пользователи | users | 10 |
| Связь с бизнесом | contact, interactionFormat | 10 |

Полнота каждого поля — 0 / 0.35 / 0.7 / 1.0 в зависимости от длины текста (пусто / <20 / <60 /
≥60 символов), для категорий из двух полей берётся среднее. Итог — сумма весов × полнота,
округление до целого. Рейтинг **пересчитывается автоматически при каждом сохранении карточки**
(и вживую при наборе текста на экране редактирования).

Уровни: **0–39 черновик · 40–69 рабочая · 70–89 готовая · 90–100 приоритетная**. Низкий
рейтинг не скрывает задачу из каталога — только помечает как требующую уточнения, ровно как
написано в кейсе.

## Правила каталога

- Видны только задачи со статусом `published` (то есть подтверждённые бизнесом на шаге 3).
- Сортировка по умолчанию — по рейтингу (по убыванию), также доступны «по возрастанию» и «сначала новые».
- Фильтры — по отрасли и по уровню готовности.
- Отклики не ограничены количеством; одна задача может получить сколько угодно откликов от
  разных команд.
- Выбор команды — только вручную, кнопками «Одобрить заявку/Отклонить» в разделе «Входящие отклики» у
  бизнеса; можно принять одну, несколько или ни одной. После принятия можно проставить
  «баллы за фактический прогресс» — это и есть шаг 8 сценария («результат»), сделан
  максимально просто, без отдельного трекера прогресса (он явно исключён из объёма кейса).

## AI-функция

Единственная обязательная по кейсу AI-функция (`js/ai.js`), в два вызова:

1. **Анализ черновика → уточняющие вопросы.** Вход: текст черновика + отрасль. Выход: строгий
   JSON `{ missing: [...], questions: [{category, text}] }`, минимум 3 вопроса.
2. **Ответы → карточка.** Вход: черновик + пары вопрос/ответ. Выход: строгий JSON с 10 полями
   карточки. Промпт явно запрещает модели придумывать факты сверх сказанного пользователем.

Оба вызова сначала пробуют внешний OpenAI-совместимый Chat Completions API (настраивается в
«Настройки AI» — endpoint, модель, ключ хранится только в localStorage браузера), и при любой
ошибке (нет ключа, сеть недоступна, ответ не парсится в JSON) **автоматически откатываются на
локальную офлайн-заглушку** на ключевых словах — она включена по умолчанию, чтобы демо не
зависело от интернета. Сформированная карточка **всегда остаётся редактируемой** и требует
явного подтверждения человеком перед публикацией. На экране карточки есть раскрывающаяся
панель «Как это считает AI» — показывает реальный промпт и источник последнего ответа
(внешняя модель / заглушка), это и есть требуемая на защите прозрачность промпта и
формата входа/выхода.

Чтобы подключить свой Anthropic/OpenAI-совместимый ключ: «Настройки AI» → источник «Внешний
API» → указать endpoint и модель. Для Anthropic `/v1/messages` потребуется адаптировать тело
запроса в `callChatCompletion()` (`js/ai.js`) — формат сообщений немного отличается от
OpenAI, транспортная функция вынесена отдельно именно для такой замены.

## Тестовые сценарии (для демонстрации)

Готовые данные (`data/seed.js`, минимальные объёмы по п.6 кейса): 5 примеров черновиков разной
полноты, 5 профилей команд, 5 уже опубликованных задач на разных уровнях готовности, 5
откликов с разными статусами (в том числе один уже принятый, один отклонённый).

Сценарий для защиты (шаг за шагом = обязательная демонстрация из кейса):
1. Роль «Бизнес» → «Новая задача» → просмотреть и вставить слабый пример черновика (розница или
   образование) → «Проанализировать».
2. Ответить на уточняющие вопросы (или пропустить) → «Сформировать карточку».
3. Дозаполнить пару полей вручную на глазах у жюри — показать, как растёт число в панели
   рейтинга и меняется уровень.
4. «Подтвердить и опубликовать в каталог».
5. Переключиться на «Я студенческая команда» → «Каталог задач» → отсортировать/отфильтровать →
   открыть только что опубликованную задачу → отправить отклик.
6. Вернуться в роль «Бизнес» → «Входящие отклики» → выбрать задачу → вручную одобрить отклик
   → проставить баллы за прогресс.

## Проверка

`test/smoke.js` — сквозной smoke-тест на jsdom, прогоняет ровно сценарий выше программно
(черновик → вопросы → карточка → публикация → отклик → принятие) и проверяет, что нигде не
падает JS-исключение. Запуск:
```
npm install jsdom
npm test
```
Не обязателен для работы приложения — только для проверки, что правки (в том числе сделанные
другой моделью) ничего не сломали.

## Что осознанно не сделано (по п.7 кейса «Ограничение объёма»)

Полноценная регистрация и роли, реалтайм-чат и уведомления, календарь, файловое хранилище,
обучение собственной ML-модели/векторная БД, мобильная адаптация как отдельная задача (базовая
адаптивность есть), полноценный трекер прогресса — вместо него простое поле «баллы за
прогресс» у принятого отклика.

## Что стоит доделать дальше

- Реальный AI-провайдер вместо заглушки (сейчас работает и без него).
- Рекомендации задач студентам по интересам/навыкам команды (`data/seed.js` уже содержит
  профили команд с интересами и навыками — сейчас они используются только как быстрый выбор в
  форме отклика, матчинг с каталогом не реализован).
- Более умная эвристика полноты полей в `js/rating.js` (сейчас — по длине текста; можно
  дополнить проверкой на конкретику через тот же AI-вызов).
